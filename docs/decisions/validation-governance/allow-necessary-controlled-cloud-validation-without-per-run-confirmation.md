## 目的
- 让当前任务确实需要、但本机无法取得的环境证据能够通过已确认的受控远端路径补足。
- 把持续授权限制在形成该证据所需的最小动作范围内。

## 背景
- Windows、Linux 或其它目标环境可能不在当前运行时中，仅凭本机结果不能证明对应行为。
- 用户已经明确持续授权，后续这类必要验证不需要在每次执行前重新请求同一项远端授权。
- 具体 workflow、命令和触发机制会随当前工具链变化，不应固化为长期决策。

## 决策
- 采用: 当当前任务的验收确实需要本机不存在的执行环境，且没有更高优先级限制时，可以无需再次询问，创建或更新临时受控验证分支、推送只含待验证提交的最小变更，并为同一 commit/ref 触发现有云端验证和读取结果。
- 采用: 云端结果只证明实际运行的对应环境，不放宽本机检查、其它平台证据或任务验收要求。
- 采用: 精确 workflow、CLI 和触发方式由当时的 CI 与工具链 owner 决定；长期授权不依赖固定 `gh` 子命令或 branch-push trigger。
- 采用: 持续授权不包含创建或合并 PR、推送普通工作分支、修改 CI、打 tag、发布、删除本地或远端分支，以及与取得该证据无关的远端写入。
