## 目的

- 让每个项目 Skill 都能用具体任务说明自己相对当前 agent 能力和项目 owner 文档新增了什么可验证能力。
- 控制常驻触发元数据、按需正文、上游分发文件和项目术语同步带来的总体维护面。

## 背景

- 普通代码审查、调试、增量实现、TDD、来源核实、API/CI 设计和可读性重构已经由 agent 能力、`AGENTS.md`、编码规范、测试策略、工程工具链和具体行为 owner 共同约束。
- 为每种工程动作建立 Skill 不会自动增加能力，反而可能让一个任务同时触发多套相近流程，并使非 owner 文档复制 Current 产品术语。
- 确定性工具的精确用法、持久 artifact 的结构与生命周期，以及稳定但通常不会自然恢复的专门判断方法，仍能通过 Skill 提供清楚的新增能力。
- 共享契约公约数判断具有独立的场景与义务比较方法；基于测量的性能优化具有 baseline、瓶颈隔离和同 workload 重测流程。这两类方法不等同于普通“写好代码”提示。

## 决策

- 采用: 项目级 Skill 只有在具体任务能够说明独立增量，并至少满足一项准入条件时才进入仓库：
  1. **确定性工具**：工具语法、安全边界或可复现操作无法从普通命令使用可靠恢复，需要专门说明、脚本或参考。
  2. **持久载体**：Skill 拥有 artifact、schema、生命周期、索引或维护命令，删除后会失去项目采用的操作契约。
  3. **专门方法**：流程具有稳定输入、判断步骤、证据和停止条件，会反复使用，并且不适合由现有 owner 文档承接。
- 采用: `common-denominator-design` 的共享契约边界判断和 `performance-optimization` 的测量驱动流程满足专门方法门槛；它们仍只承接各自方法，不复制 Docnav Current 产品契约。
- 采用: 保留的 Skill 从项目 owner 文档读取 Current 语义，并以窄触发条件限制适用范围；Current 产品规则不在 Skill 中形成第二个 owner。
- 边界: 本决策只约束仓库内的项目级 Skill；系统 Skill、个人 Skill 和插件 Skill 分别服从其安装与生命周期边界。
- 边界: 精确安装集合由仓库当前文件证明，准入判断本身不产生安装、删除或实施授权；具体变更仍需当前任务授权。
- 不采用: 仅按编码、调试、审查、TDD、增量交付、API 或 CI/CD 等工程动作拆分项目 Skill，也不把被删除 Skill 的全文迁入 `AGENTS.md`。不能证明独立增量的候选留在对话、个人实验或外部插件中。
