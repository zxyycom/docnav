## 目的
- 允许把真实混合、可独立演进的旧决策及时拆成可单独使用的活动判断。
- 在当前工具不支持 decomposition provenance 时，优先保证决策语义真实，不用伪造关系换取完整 trace。

## 背景
- 当前关系类型只表达 `修订`、`替代`、`判定无效` 和 `归并` 等真实语义演进，不表达一般性的“拆分自”或文本来源。
- 当前 CLI 在第一个 successor 建立时归档直接前序；后续 successor 无法再把同一个已归档前序作为建立事务中的直接关系目标。
- 等待上游关系模型或 CLI 更新会让已确认的原子化长期判断继续被混合记录阻塞，而把每个切片都标成 `修订` 又会虚构它们各自保留了旧决策主体。

## 决策
- 采用: 当一个已建立决策确实包含可独立修改、具有不同 owner 或不同 alignment 的判断，并且拆分属于当前决策维护任务的范围时，可以直接建立多个独立 successor，无需再次请求同类拆分许可，也不等待上游 decomposition 支持。
- 采用: 对每个 successor 分别判断现有关系类型是否真实适用；能够真实表达演进的 successor 正常记录直接前序关系，其余 successor 可以使用空关系建立。
- 采用: 由此造成的 predecessor/successor trace 不完整是已接受的暂时 lineage 损失，不构成阻塞，也不通过伪造 `修订`、`替代`、`归并` 或其它关系补齐。
- 采用: Relationless successor 可以在背景中保留必要的拆分上下文，但这不是建立前置，也不冒充机器可查询关系。
- 采用: 上游提供明确的 decomposition/provenance 关系和可恢复 CLI 事务后，新的拆分改用正式能力；既有缺口不要求批量追溯修复，除非后续任务明确需要并授权迁移。
- 边界: 现有关系能够真实、完整表达一对一或多前序演进时仍必须记录；本决策只放宽当前模型无法表示的一旧多新拆分，不允许任意省略可表达关系。
